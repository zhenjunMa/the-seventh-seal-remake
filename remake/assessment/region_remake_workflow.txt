第七封印 · 全区域重制工作方法
更新：2026-10-26；基于火之谷及外层白木森林的实际接入、来源恢复和回归经验。
本文件维护可复用方法和已踩过的坑。当前区域是否完成、尚存卡点和验收结果只维护在validation_design.txt；不能用本文的方法说明代替完成报告。

一、区域的交付单位
“区域完成”包含该区域在原版实际使用的所有阶段，不只是地图画面能打开。每个阶段需要核对进入条件、参与队伍、NPC显隐／位置／动作／对白、任务与物品、地形事件、演出、剧情战斗、离开／返回和保存恢复。
分别记录四种状态：来源已收录、运行已登记、行为已实现、流程已验收。全量来源库可以远大于可执行内容；所有地图登记成功也不能推出所有剧情完成。
同一区域可能由其他区域推进的旗标改变。区域边界是交付边界，不能截断来源依赖：需要列出外部写入者、进入演出调用者与交接时应具备的状态。暂未重制区域外前置时，可用有来源、状态一致的阶段存档验收区域内流程；必须标明该测试从交接点开始，不能称完整主线实玩。随意设置几个旗标只能证明局部布局。

二、内容模型与文件职责
原始层：原DAT／TLK／ANM／CHR／MAG／道具／SCN等只读，索引保留文件SHA、原编号、偏移、记录长度、原字节和行为证据。导出器不修改原存档，不把猜测写成来源事实。
内容层：runtime/web/data/runtime_content.json登记实际开放的地图、角色、技能、演出和入口；web/content放新增事件与任务。道具和技能参数继续使用统一config文件的稀疏parameters，不新增区域或角色专用数值覆盖。
运行层：TLK和自编事件编译成StoryFlow，由同一个StoryFlowRunner执行。ChapterRunner提供世界事务、原条件／变更和游戏行为适配；ANM负责演出指令，浏览器控制器负责视图、输入、媒体和生命周期。新区域不再创建另一套剧情VM。
生成层：chapter_story和chapter_map_resources保留来源台账；data/story为按地图加载的紧凑运行包，不能手改。任务状态读取已有旗标、物品或世界事实，领奖在同一剧情事务中提交，不重复保存一份容易失步的任务进度。
NPC以“地图ID＋原slot”标识实例；ROLE／DGP编号是共享素材身份。相同名字或图像不合并实例；同一人物跨地图是否属于同一剧情身份，要由来源事件关系证明。

三、先建立全量清单，再分阶段接入
1. 发现区域：用原地图名称和真实DAT连接确定成员；文件前缀仅用于候选查找。保留同场景变体的原ID、旗标和NPC表，不能按“-1／-2”猜时间顺序。
2. 导出地图网格、入口标记、各类描述符、物件、NPC表、加载／到达入口，以及所有TLK记录和选择分支。没有TLK的地图、没有独立对白入口的NPC都明确保留，不编造空对白。
3. 扫描全游戏调用关系：区域内调用的ANM、加载区域地图的ANM，以及这些ANM的区域外TLK／DAT调用者；另外反查本区所用旗标在其他区域的读写。只扫本区对白会漏掉进入链。
4. 建立有向图，分开物理出口、TLK传送、ANM地图加载和外部交接。无向连通只证明连接，不证明玩家能从入口到达。无网格引用的描述符不能当作已经可触发的事件。
5. 列出阶段矩阵：每个实际入口条件、原旗标读写者、地图变体、有效队伍、NPC差异、必要演出／战斗、离开条件及重进结果。阶段名字只是说明，判断仍使用原世界事实，不能用进入次数替代。
6. 用只读能力检查找出每个入口可达的未知条件、变更、ANM模式、技能和媒体。先恢复通用处理器及来源回归，再开放入口；不以跳过命令、自动打败Boss、删除角色或固定播放一段对白冒充完成。
7. 继续展开奖励依赖：学会技能的source ID要解析到真实角色索引，并检查该招的菜单、目标、效果和表现能否使用；解锁配方要区分解锁记录、合成规则及原合成入口。通用“学习／解锁”变更通过preflight，仍可能留下不可用奖励。全区域验收必须把这类引用展开，不能以learned已经保存结束核查。
8. 同样展开物品的“取得→卸下／使用→再次装备／镶嵌→保存恢复”。已有初装不代表物品注册允许再次装备；TLK成功发奖也不代表奖励可用。按已登记队友的原初装和已登记剧情的真实授予推导所需能力，先检查装备是否只有已恢复的数值字段，保留显式禁用和稀疏调参。不能为了修复一件奖励而开放整个道具库，或把未恢复的被动效果当作普通属性。

火之谷样本：21张DAT、147个NPC实例中63个有独立TLK索引入口，其余84个仍可能在演出中被使用。三个祭坛变体M17030／M17030-1／M17030-2分别使用flag11／471／469。M17032入口2按真实旗标选择这些阶段；flag12:1的写入者在区域外M73014，不能伪造“第二次访问”。

四、来源格式和推断的常见陷阱
DAT +0x8A是加载布局TLK，+0x13A是实际到达TLK。旧猜测+0x11E在样本中为0；TLK slot499也有独立用途，不能把三者混用。M17010加载从r69开始，到达从r90开始。
加载布局要在每次prepare时根据将要显示的世界快照投影。读档、缩略图和预览不能重播到达事件。异步读档尤其不能使用当前旧world来决定新存档NPC布局；玩家保存的位置仍然优先于加载演出的默认队伍站位。
DAT描述符有0x2B紧凑格式和0x42格式：紧凑表的字段在+26／27／28单字节，完整表在+26／2A／2E DWORD。state0物理传送、state1演出和state2 TLK要分别解码。TLK kind2的+2F是目标DAT入口标记，不是TLK跳转记录。
地图素材目录按DAT +0x14E的Mapm资源基名寻找。M17024实际复用mapm/m01021_2/026.dgp，祭坛变体复用mapm/m17030；不能由地图文件名拼出一个假目录。
物件要同时盘点可交互列表、更新队列和实际可见像素。CF4等原字段只表示候选行为，不保证对象会进入执行队列：M17030水晶DGP为1帧0动作，原410850不将它加入更新／选择列表，因此不能照4137C0理论分支增造拾取。反过来，没有indexed光效也不等于静态：火之谷9处CF1主层有真实逐帧变化，旧光效导出器的indexed_auxiliary筛选会漏掉它们；另外23处源帧全透明，不应添加虚构视觉。按真实DGP动作数、原入队条件、全部通道和源帧像素确定运行责任，再分别验收显示、动画和互动。
白木森林CF4箱的+48是原加载时重建的交互序号，钥匙条件在+F2；奖励为+54起十个DWORD。字段含义须追到加载、交互和更新三条路径，不按数值分布猜“元素类型”。即时完成4137C0与存档重载40CFE0的layer可不同，验证要覆盖开箱动画结束和重新进入后的实际绘制顺序。现有事务若未恢复原掉落池，应明确背包满时的原子重试适配，不能丢失奖励或冒称全部掉落语义相同。
没有TLK不代表没有原互动。DAT-only地图可使用同一ChapterRunner的直接物件事务；来源表明确对白文件缺失，records为空且不生成虚构Flow，运行包读取也不能无条件要求flow_id。旧测试遍历整表时按显式来源状态处理合法空表，原有地图／像素范围另作固定基线，新增内容单独逐源核对。
CF1单动作初始化也有来源顺序：410850先抽FF，再按B4选择固定间隔或“源间隔＋CRT半区间”，初次显示帧0；4137C0每次访问只走一帧并重置DD，不做追帧。个体隐藏不等于移出更新队列。ANM控制NPC时，地图物件仍应继续更新；不能把“剧情视图活跃”当作所有场景时钟暂停。场景独立的视觉CRT与持久遇敌／战斗RNG分开记录，这种适配不声称恢复了原程序全局CRT的调度。
ANM名字不表示执行地图。m17010-3除了M17020中的无cells描述符，还由M03039.TLK:r13调用；它先做队伍操作，再加载M17010，最后加载M17032。索引要保留区域外调用者；不能把无cells描述符补一块自选地形当入口。没有opcode10的演出则必须继承实际调用地图，不能从文件名猜。
区域外命名的演出也可能包含本区不可省略的内容。m01050-2的44命令先在炎城交接，再进入火之谷移动居民并调用M17010:r5链，开启10:1后的朱特阶段。只设置交接旗标会漏掉整段区域演出。应接入完整源程序及必需的外部地图／入口；若前置区域尚未重制，声明开发交接条件，不能裁一段ANM后半部或伪造本区地形入口。外部地图仅登记实际需要的NPC时，能力准入也必须沿已登记入口和ANM调用的可达记录收集，不能把同张TLK其他NPC的奖励一并开放。
ANM编号从0计，TLK记录从1计；ANM分支目标又使用原1起始命令号。日志同时保留source offset，防止相差一条而未察觉。opcode255是否结束必须查原分派，火之谷样本的原default是继续执行。
ANM33的+25低字节是到达朝向：0保持、1..8减一；不是移动速度。镜头opcode11和人物移动也不能共用未经证明的位移步长。opcode62／63不是统一的播放／停止：要恢复持续句柄、地图BGM静音／恢复和结束后释放的实际分支。
沿用旧素材生产者的地图也要核对新运行规则所需字段。火之谷入口旧地图包缺镜头步长，静态入口与headless剧情都通过，浏览器才在ANM镜头处失败。完整DAT头已随来源表保存时，可在地图prepare按同一DAT路径／SHA恢复+0x144人物与+0x145镜头步长，并核对已有字段，避免默认值掩盖缺项；不必为补头字段重建旧地图像素或运行会覆盖新战斗表的历史路线工具。
NPC的DAT动作绑定也可能只是未初始化模板。原469F50先清20个通道，再按ROLE动作raw+7E取第一匹配索引；仅缺walk时继承idle。M17030-2丁多模板全FF，但其DGP动作0／1明确对应idle／walk，直接拿模板会在后期演出command73失败。保留DAT原绑定，单独派生运行绑定，普通NPC与ANM共用；不要按人物编号补动作。原run缺失分支还存在写walk自身的行为，不能凭直觉改成run=walk。
DGP动作帧可以引用全局帧池。朱特反应动作id9的first36＋局部0..6有效，尽管动作组声明frame_count为6；必须按实际全局池边界验证，不能裁掉最后一帧或篡改原帧数使检查通过。
编码行数也不总等于显示矩形高度。M01050/004.dgp首帧显示173×175，实际存有200个完整RLE行，尾25行5576字节；原52AE7F只绘制geometry175行。解码器应严审完整存储流、记录裁外行的偏移／SHA，PNG只输出声明矩形。不能把非空尾随数据直接当padding，也不能扩大画布。用原blit指令oracle、独立全流审计和最终RGBA三者比对，同时保留旧帧像素基线，避免为新地图放松全部资源检查。
同一动作被技能与生命周期引用时，物理图集可能需要覆盖更大的全局帧范围。合并须核对同一DGP／CHR身份、原172字节动作、原声明帧数、first_frame、方向与间隔，并证明扩展帧确实被原CHR使用；保留原声明与实际帧池两个字段。主层／光效映射和重叠像素逐一相同后才选较大的图集，不以放宽SHA或覆盖元数据解决打包冲突。
原条件raw+0B有语义，不能只导出三项DWORD。条件1有对象状态反转，4要考虑背包及已装备／已镶嵌物件，10判断原活跃队员slot。技能学习按原技能ID查所属索引，不能把源ID72误当数组索引72。
“已经学会”与“战斗处理器支持”分开；“配方解锁”与“合成系统可用”分开。CHR奖励槽存在也不代表一定掉落，要检查道具掉率和RNG分支。随机遇敌频率为0不代表没有剧情战斗。
TLK kind5的文本区包含stage和最多6个敌人文件名，每个20字节，以首个NUL截断。NUL后的垃圾尾不能当另一个敌人。M17030-2:r31明确使用stage12.scn和032.dgp，不能随机抽STG组或套森林背景。
来源文件名语法也不等于当前运行角色编号。M01050未开放的r103实际使用031A1.dgp／031B2.dgp，完整表编译仍须保留这些合法basename及槽位；不能用三位运行ID的正则丢弃或截短它们。运行执行另查已登记舞台、原角色身份和可用处理器，未开放分支继续阻断。新增交接地图后，除规则与OpeningView回归外，应先对全部运行地图做最终剧情包只读编译，防止全表紧凑化在长时间素材构建之后才失败。
媒体扩展名不等于编码。MANYANSHORT.wav实际为MP3，应保留原字节并用真实.mp3后缀；影片保留尺寸、帧率、全帧数和音频，浏览器转码的质量与可能的显式播放增益另记，不能静音或用占位片段代替。
原生浏览器函数不能直接保存到对象后以对象方法调用：setInterval／clearInterval在真实Window上有接收者要求，宽松Node mock会掩盖Illegal invocation。默认依赖用显式globalThis包装，测试除注入假媒体外还应覆盖默认适配；实际首段声音、影片播放及清理仍需浏览器复验。缺音效应保留源token、文件缺项和引用偏移，邻近编号或同名不同扩展不能自动替代。
缺失文件还要区分“来源包真的没有”和“原读取器存在别名”。不能看到close.mp3与_close.wav字节相同就认定它们替代close.wav。沿实际调用追到同包音频库的文件打开：本次GAME的52D582经Mss32.dll的AIL_quick_load、AIL_file_read最终把原字面路径传给CreateFileA，失败直接返回；库的线程／Win32s分派不等于改名回退。记录程序及DLL身份、真实路径、调用分支和失败语义后，才决定补原文件或恢复有依据的通用解析；不能逐个声音写猜测别名。
原Bink解码成浮点PCM后可能超过±1。直接转AAC会削波；火之谷20／24／25使用显式0.5编码余量和2倍播放增益，按恢复后PCM核对质量。仅检查“有音轨”会漏掉失真，需检查完整解码、帧数、SSIM及音频误差。
统一配置的数值校验也必须按实际原取值函数区分。娃蒂援攻003／33的物理倍率原字段为(200,0)，41D990／41C610对high<=low固定返回low且不抽随机；旧min<=max校验会误阻断原技能。允许这类原语义时仍校验32位范围、正span溢出与两端上限；速度采样走另一条规则，不能一并放松。普通配置迁移保留稀疏调参，不通过reset或改原200／0解决。
CHR命令和技能名称不能决定效果。032的技能11有18次真实接触，命令7／8改变显隐并消耗各自RNG；004的恢复／清状态走原support路径，不套伤害随机。原无效字段必须忽略，不能因为数值非零就虚构效果；同一状态的周期伤害、死亡和受击要在同一原时钟顺序处理。
药品的HP／MP字段全0也不代表没有作用。火蜥之血272的效果来自原C6状态块id5／mode1和_iReSTfz.dgp：508BB0先执行重复guard，再移除首个匹配状态并重聚合，不抽随机，不清除全部状态。原返回0时仍可播放用药动作17和特效，但不能扣库存；途中目标变成倒下／免疫则不播放接触效果也不扣。场外47D960对它的全零数值直接返回失败。配置、菜单、调度、实际接触、素材、失败消费与重复接触必须闭包，不可把所有药品套进简单恢复函数。
CHR文件值还可能被加载器改写。火之谷整战曾把032原code97..101送入组合，实际正常入口461ED0→4451C0先把00679C6C置0，再由4FED00对技能+19归一：type低四位0或flags bit8未置位时code为0，其余按a..y／A继续赋值。GAME.exe镜像初值却是1，必须沿真实调用入口追到模式写入，不能只看静态初值。把这种规则实现为不可变来源上的运行派生，保留原CHR与配置；非0模式与原抽随机顺序分别回归，不给缺marker动作编造fallback。
显示HP与死亡资格也不能混为一谈。装备加成可能让原rawHP已为0的角色仍显示正HP；原狼炎仍会置死亡进程类别。活队伍、调度与终局按有来源的类别处理，保留显示HP公式；空中仍要等落地／死亡回执，不可据正显示HP复活角色，也不可在空中提前发奖或判败。
同一判定还要追到最后的返回策略。曾在stage12真实全员败北后，战斗核心已确认state7且死亡回执完成，后置planPartyDefeat仍用“全部显示HP=0”拒绝，导致不能进入game-over。只修调度与终局采样仍会漏这一道门。应从真实最终快照验证“战斗结束→资源结算→剧情失败／回滚→败北影片→标题”，并保留健在、逃走和未落地状态的反例，不为了通过校验强制清零原显示HP。
复活目标也不能反过来要求显示HP为0。原类别4至7的资格应由同一来源函数判断，菜单候选、排队目标、就绪派发和接触执行都要共用，否则菜单能选仍会在后面被第二道HP门控拒绝。复活切换life epoch使旧死亡回执失效，但不凭空清零Z；原浮空时钟和落地过程继续，重复接触与旧回执不得再次扣MP或抽随机。

五、事务、队伍与资源生命周期
整条剧情使用同一draft。旗标、奖励、队伍、传送及剧情战斗结果成功后统一提交；加载失败、取消和world revision变化均不消费奖励、不覆盖新进度。渲染场景与镜头也要回滚，不能只有世界数据回滚。
准备目标地图时持有来源／目标地图及演出的lease；每次await后检查取消和会话身份。运行包依赖按实际ANM地图并集加载，避免递归预载全区或缓存淘汰正在执行的地图。释放在finally，长流程需核对资源数量。
队伍活跃名单与拥有角色分开。离队保留成长、HP／MP、学习、装备、晶石、快捷与技巧、遇敌进度；再次入队恢复同一个实例。原45E560只清对应阵型槽，不压缩空位；满四人的原入队为无写入返回，不能重置或删除旧成员。
候补存档是重制的持久封装，不是新增原版剧情规则。物品唯一性和装备归属需同时检查active＋reserve；战斗、菜单行动与条件10仍检查活跃队员。控制角色opcode36 mode3改变地图控制对象，不等同于入队。
暂停、页面隐藏、取消、读档和场景销毁要贯穿对白、wait、位移、镜头、影片、声音、战斗及返回游标。剧情演出中进战斗后不能重启ANM或提前提交战前旗标。
剧情战使用私有世界继续运行正常战斗调度、AI、技能和结算，胜利／逃走后合并回外层draft；败北或后续事件失败回滚。战斗不能直接提交外层世界，也不能少算原入战转场RNG。浏览器视觉转场的随机与原数值随机要写明边界。
剧情结束后的全局副作用也属于内容闭包。火之谷终章M17023:r47写1999:1，但原477330是在ANM全结束／清理后才检查，并进419E90(mode2)标题、禁用继续；只实现通用写旗标会漏掉真正的游戏结束。原MenuCode持久标记与世界存档分开；重制对应独立元数据，不写原注册表，不自动保存，不凭一个标志宣称特典全恢复。提交前仅暂存terminal请求，外层成功后再显示标题；到达事件需要afterCommit，避免提交顺序颠倒。
异步准备JSON／图片／HUD时，取消必须立即结束等待；底层旧请求完成也不能安装视图。HUD先在脱离页面的节点中准备，确认会话身份后再挂载；构造器若偷偷通过document.getElementById复用旧按钮，会把旧战斗UI搬走。清理未启动的战斗还须允许state为空，旧notify也要检查ownership。

六、验证顺序与证据强度
来源检查：身份、文件SHA、偏移、记录字节、解析边界；需要行为解释时保存原程序对应分支和调用关系。外部输入不足要写明具体文件／版本／缺少的观察。
规则回归：真实记录的正反分支、RNG消耗、奖励一次性、成长保留、传送标记、取消／失败／重复／读档。保持原字节、像素及oracle断言；扩大内容时修正旧测试的固定角色数量假设，不能降低数值／图像精度门槛。
仅给ANM传空hooks只能验证指令控制流，抓不到真实OpeningView的角色、动作、镜头与资源交接缺项。火之谷先后有镜头头字段和丁多动作绑定在这种测试下漏检。为长演出增加真实StoryRepository／MapController／OpeningView／ActionClock的加速闭包回归，逐条核原74字节命令及每次显示描述；媒体和战斗若使用接口替身必须明确，仍需真实媒体、原数值战斗和浏览器收尾。
演出结束还要覆盖正式控制器的外层提交。火之谷终章隐藏的受控角色仍保留调用地图坐标；从任意可达入口运行时，该坐标可能落在最终地图的障碍格。只拿自选的可通行初始坐标跑OpeningView会漏检。应按原结束分派区分“恢复探索”与“提交后直接标题”，核对世界校验、视图交接及afterCommit的完整顺序；不得为通过校验擅自传送人物到其他演员位置，或提前切标题掩盖回滚。
战斗依赖要沿“敌人实际已学技能→真实接触→所有可能玩家目标→原反应／动作→竖直状态／死亡／终局”展开。火之谷032的伤害／RNG和18接触独立检查通过后，完整源战斗仍在第6次输入暴露技能9／10／11要求玩家ID5浮空受击。只测敌人被打或只看+62为1的技能会漏掉这条链；不能靠关闭原招式通过。content依赖需检查敌方反应闭包，最终仍跑不注入伤害或胜利的整场回放。
新异步载体不能套旧的串行动作结束规则。原wait0载体按自己的DGP间隔继续接触，角色动作结束后可仲裁下一行动，载体保留施放时的source skill，不能借迟到接触把人物切回旧动作。终局锁定、奖励RNG、剩余载体和视觉清理分开追踪，以原分派顺序核对；不能为了省实现把wait0改成wait-all。
援攻特效不能只根据已有光效层判断是否完成。cvt_p001／002包含阴影、普通主层和intrinsic加色层，需要逐层从原DGP独立解码核对；只有加色层的旧导出器会丢主层。源type0学会后仍可能不进入菜单，不能把“奖励要可用”理解为擅自修改原技能类型。
统一构建：build_runtime.py先preflight，再按目标构建，查看独立run.json和step记录。源码登记变动用content；只改自编事件／任务可用story-pack。普通导出保留调参，--force只强制重建，不是--reset。共享工作区不能同时跑多个会改build_state／生成表的构建。
共享生成表必须只有一个生产者。例如forest_status同时包含已接入敌人与玩家所需状态，由enemies步骤统一生产，party-skills只校验引用。输入指纹要覆盖所有实际读取的角色／状态／效果DGP；只列主要CHR会使缓存误认为无需重建。依赖和输出都同步到tool_index与派生文档。
导出器的模块级测试不能代替真实CLI子进程。嵌入式隔离Python可能启用isolated／safe_path并忽略PYTHONPATH，不自动将脚本目录加入搜索路径；曾有items在测试进程可import、统一构建却找不到同目录content_registration。工具须按现有规范从__file__显式定位自身依赖，并用build.execute真实子进程、声明输入和缓存路径回归，不能靠开发终端的隐含路径通过。
覆盖数量也必须带明确范围。新增必要的外区交接地图后，旧CF1测试把全局56个当成永远不变的总量，实际变为69个。修复测试时保留旧范围56个／120帧与火谷32个的断言，再独立按M01050原DAT核对新增13个记录、两个原DGP及四帧主层／加色层像素；不能只把56改成69。区分旧基线与新增来源，既避免旧测试误报，也避免新增内容掩盖旧范围退步。
历史预览的固定角色表与正式当前内容分开验证。旧森林四角色／首接触预览仍按原范围核对；正式enemy／party银行按当前登记全量检查。不能因为新增032就把旧113条oracle断言放宽，也不能拿旧四角色表代替当前五角色依赖。打包工具也需明确每份清单的覆盖范围，并把子进程stderr写进步骤日志，否则只看到CalledProcessError很难定位根因。
当前构建签名保守包含全部tools与core，修改规则后可能重建与本次规则无直接关系的素材。先收口生产代码，再做最终构建与浏览器指纹，避免一边验收一边改模块；大图集生产完成不表示后续字体、打包和登记已成功。
全来源配置中的side=source接入运行时会改变身份分类。需要核实原角色／索引、名称及SHA后做明确迁移，共同parameters保留，旧耗蓝字段按已恢复语义转换；不能用reset掩盖错配。扩大角色登记还会触发旧导出器“导出这个角色全部特殊动作”的隐含假设，必须按实际必需记录检查能力，而不是放松命令验证。
资源检查：verify_phaser.mjs --assets核对当前清单和媒体；readiness只保证已登记入口的已知能力，不是全区域完成率。未登记入口需要与全量索引对照。
浏览器检查：通过正式页面的实际操作／导入功能运行，记录开始存档、操作、结束存档、源码／配置／媒体指纹、截图和控制台错误。布局夹具、定向事件、自然走图、完整阶段流程、原GAME.exe观察分别说明，不能相互替代。
每个阶段至少覆盖：进入前后和保存重载；NPC显隐／位置／对白；任务首领／重复交互；出口正向／拒绝；战斗胜败／返回；途中失败／取消；再次进入无重复奖励。最终阶段矩阵里每一项都要有当次证据或具体阻断。
已有报告选取必须匹配实际输出的构建步骤；旧日期文件的SHA变更只允许有明确旧值／新值／唯一路径的迁移记录。不得为了通过检查覆盖历史基线。

七、证据维护和中断续做
证据和媒体目录被Git忽略。交接代码时同时按local_materials.txt交接相对路径、SHA、环境和恢复方式；不要假设别人克隆后就有本机浏览器记录或native伪代码。
旧测试可能有写历史报告的副作用。运行Node回归使用 --import ./remake/runtime/tests/preserve_history.mjs；新报告写current或新的有日期目录。曾有slice定向测试覆盖旧slice_verification_20261011.json，原字节无备份不能复原，已记录history_report_incident.json；不能把局部重跑伪装成原历史报告。
中断后先查当前diff、构建run.json、source SHA、工作计划和未结束的会话，不清空已有成果、不重跑会覆盖证据的命令。新的验证绑定当前指纹；旧成功结果不能自动升级为新代码验收。
已用于浏览器观察的开发存档也是证据输入。新构建复用时，保留原文件／SHA，先用当前WorldStore校验再记录本次操作；不要重新生成同名存档更新saved_at，导致旧截图和日志所指的输入字节消失。确需改变准备内容时，另建目录或版本名，并保存差异和准备来源。
卡点要写成可以执行的交接项：稳定编号、实际触发路径、缺口行为、原文件／偏移／函数、已经查过什么、当前如何阻断、需要的证据／实现及解除后的验收。笼统写“以后完善剧情”无法支持其他区域复用。

八、接手下一个区域时的执行顺序
先读AGENTS、当前计划、story_guide、config_guide和local_materials，确认原输入身份及本地证据是否齐全；在已有diff上续做，不重新初始化配置。
建立区域来源清单与阶段矩阵后，登记runtime_content并准备chapter-story源表。已有工具支持的来源使用统一入口；遇到新文件格式先补解析和边界回归，不直接编辑生成JSON。
在仓库根目录依次执行（Windows的python需指向Python 3）：
  python -B remake/runtime/tools/build_runtime.py --target chapter-story --run
  python -B remake/runtime/tools/build_runtime.py --target content --preflight
  python -B remake/runtime/tools/build_runtime.py --target content --run
  python -B remake/runtime/tools/sync_tool_docs.py --check
  node remake/runtime/tools/verify_phaser.mjs --assets
火之谷专属索引使用fire-valley-index目标；其他区域应建立对应的通用来源清单／注册目标，不能借用该名字输出另一地区。各命令前置、选项及首次构建限制仍以tools/README为准。
每个阶段记录：来源条件与外部写入者；实际入口；地图变体；队伍及NPC差异；对白／选项；奖励及使用链；战斗／演出；退出／重进；保存／恢复；失败／取消；对应证据路径与指纹。自然路线、来源交接开发档、规则回放和仅渲染检查分别标注。
修改规则后运行真正覆盖来源分支的定向测试，再做一次最终构建与完整检查；不要在每次小修改后全量重建。Node回归需带历史保护：
  node --import ./remake/runtime/tests/preserve_history.mjs --test remake/runtime/tests/test_具体模块.mjs
素材及历史材料完整、服务在8767运行时执行python -B remake/runtime/tools/verify_current.py。缺少材料则记录准确缺项并运行可执行的限定检查；不修改旧SHA以获得passed。
最后操作正式页面：从真实入口或明确声明的阶段交接点完成整段，保存新观察。关闭当前卡点必须同时更新唯一工作计划、稳定指南中受影响的规则、dated证据及本地资料索引；完成报告列出未覆盖范围和外部缺项，不把测试总数当作区域覆盖率。
