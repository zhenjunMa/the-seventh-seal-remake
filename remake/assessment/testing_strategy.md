# 第七封印 · 测试与验收规范

本文维护当前测试职责、选择原则与界面／流程验收口径；具体CLI见[工具说明](../runtime/tools/README.md#测试职责与运行)。未完成优化和当前阶段状态只在[开发计划](validation_design.md)维护。

## 当前执行边界

已实现task／phase／release／audit、递归代码依赖选择、便携结果复用、区域动态遍历分离及真实Phaser生命周期检查页。测试清单为`runtime/tests/suites.json` v2，统一执行入口为`verify_tests.py`，版本汇总为`verify_current.py`。

当前动态数据变化和结果缓存失效仍保守覆盖全部便携输入；尚未实现分地图语义依赖、完整跨区依赖图、统一阶段案例和浏览器自动调度。以下规则描述当前应执行的验收，不把后续目标字段或迁移步骤当现成功能。

## 按验证对象分工

| 层级 | 验证对象 | 内容增长方式 |
| --- | --- | --- |
| 规则 | 资格、数值、RNG、状态、移动和奖励去重；最小确定输入 | 新机制或高风险边界增加行为案例 |
| 组件 | 剧情／地图／战斗／存档事务、资源租约、取消及迟到回调 | 新系统连接或交互风险增加案例 |
| 内容 | 真实登记的身份、引用、条件、能力与资源闭包 | 扩充数据，复用共同检查器和少量真实绑定案例 |
| Phaser集成 | 实际Canvas、场景、时钟、纹理、缩放和输入连接 | 新显示机制增加少量专门场景 |
| 正式流程 | 正式入口的进入、事件、战斗、离开、保存及操作体验 | 每个新阶段一条有明确范围的事件链 |
| 来源与构建 | 原字节、解析边界、独立像素、媒体和实际CLI生产 | 新格式／变体／转换策略增加核对，既有输入复用有效结果 |

Node和Python是执行工具，不能把全部Node检查统称单测；回归可包含以上各层。假Canvas验证协议与行为，不证明真实渲染；完整事件执行也不能独立证明画面、声音与体验正确。

同机制的新宝箱、NPC、商店、技能优先扩充来源、登记和案例数据，不复制一套完整测试程序。对白／可逆布局修改不为形式增加单测；新指令、资源策略或高风险故障保留能发现实际错误的边界案例。

## 选择本次范围

| 档位 | 使用时机与范围 |
| --- | --- |
| task（默认） | 受影响规则、组件和内容，加必要核心冒烟；界面变化补对应浏览器场景 |
| phase | 共享便携检查、该区域完整动态遍历，以及声明阶段的完整事件链、失败恢复和相邻交接；当前区域参数并不自动生成事件链 |
| release | 已实现发布范围的完整自动检查、实际资源和连续流程；干净构建与支持平台单独实际验证 |
| audit | 原版来源、媒体、解析器或历史材料专项，按对应环境和范围执行 |

- 文档改动只核引用；无运行内容变化不执行游戏回归。
- 内容变化检查完整引用和开放入口准入。即使当前旗标不成立，可达未知指令或处理器仍阻断；动态流程按本次阶段和实际差异选择。
- 战斗公式、StoryFlow、存档公共结构、时钟、解析器或依赖分析变化，扩大到受影响系统及代表旧链；无法可靠分析时保守扩大。
- 固定核心冒烟保持精简，围绕启动／恢复、探索交互、战斗返回、存读档和暂停；全局基础变化扩大，孤立文案或参数变化不机械打开全部流程。
- 旧NPC多态全遍历归content-full；原字节／媒体和旧交接生成器分别归source／assets／history。支持中的旧存档兼容案例继续保留。

新增同机制内容保留其实际绑定校验和关键事件链，事务层已覆盖的等价异常不逐对象复制。代表实例按行为差异选择，不随机按地图抽取；主线前置、关键条件边界和奖励原子性不能省略。

## 结果复用与结束条件

当前runtime／content／content-full成功结果按文件保存在`runtime/.cache/test_results`，绑定全部便携代码、辅助代码、结构化数据和环境；任何相关输入变化失效。失败、跳过、损坏及执行中输入变化不生成可复用通过结果。文档、报告与缓存本身不使便携结果失效。

source、真实媒体、HTTP、history和验收工具自身检查始终执行；`--fresh`忽略便携成功缓存。来源／媒体增量生产另核实际输入、转换规则和输出SHA，文件存在或mtime相同不足以复用。跨设备图集排版可改变，可见像素与alpha仍须保持。

执行顺序为实现／构建收口→选定自动检查→受影响正式浏览器→汇总。浏览器发现问题后只重跑受影响检查和场景；有关输入未变且声明范围全部通过即结束，不自动从task升级release或追加all。缺前置、未执行、通过与复用分别报告，不能以skip充作通过。

## Phaser与异步集成

当前正式路径为Phaser 3.90.0 Canvas，输入、音频和碰撞使用现有适配器；不为未使用的物理／音频插件或WebGL增加默认验收矩阵。

| 边界 | 必查行为 |
| --- | --- |
| 场景 | 区分pause／sleep／shutdown／destroy，切回、重进和销毁不叠加监听器／任务；休眠场景仍需防外部迟到回调。 |
| 时钟 | 主动推进20ms逻辑步，覆盖阈值、多步及余量；暂停冻结，恢复首帧不补后台时间。不同delta分割在声明误差内一致。 |
| 资源 | 活动图集不提前回收，离场释放本次租约；取消准备后不安装过期纹理，预热后对象／监听／纹理数量有界，不要求全局归零。 |
| 渲染 | 核实际Canvas图层、裁切、加色、锚点、缩放与焦点；HEADLESS或假Canvas不替代像素和正式流程。 |
| 性能 | 分别测冷启动、首次进入／技能、热切换、连续战斗和释放；固定环境比较，缓存估算不等于GPU实测内存。 |

`runtime/web/tests/phaser_lifecycle.html`用合成资源核实际引擎生命周期，不读写正式存档；其通过不等于正式媒体或自然主线验收。浏览器等待使用可观察状态与有界超时，避免固定sleep；自动重试到绿不能代替定位不稳定时序。

## 界面与动态表现

以“状态、输入、时间推进、可见／可听反馈、数据提交”描述行为。对照原矩形、页原点、素材、锚点、文字、焦点和声音；原坐标统一投影至640×480后整体缩放。

| 方面 | 检查矩阵 |
| --- | --- |
| 页面 | 进入、默认焦点、空／有数据、滚动／翻页、禁用、非法确认、逐层取消、退出／再次进入、窄窗口 |
| 交互 | 键盘、鼠标、长按、重复确认、多人切换、加载／资源失败；一次操作只提交一次 |
| 时间 | 第一帧、接触、受击、末帧／循环、死亡留帧、复活取消旧动作、转场前后；长动作中输入、充槽和状态仍按规则推进 |
| 暂停 | 手动暂停、页面隐藏、恢复首帧、异步等待和退出取消；不跳等待、不留悬挂任务 |
| 声音 | 移动／确认／取消／拒绝各一次，音量／静音、媒体结束和回图BGM保持 |
| 状态 | 只改变预期字段；取消不提交，资源／库存／奖励／保存去重，旧加载不覆盖新进度 |
| 新队友 | 同时核地图、队列、状态／装备、战斗四槽、动作和保存 |

素材核主层、indexed加色、透明／遮罩和锚点，导出PNG后再核解码一致。源像素可精确比较；浏览器动态画面固定资源、缩放和采样时刻，以稳定区域、容差和人工体验判断，不把跨设备全屏逐像素相等设为默认门槛。

截图取可见`#phaserHost canvas`或整个游戏区域；透明兼容`#stage`／`#battleCanvas`不代表当前可见场景。内部转场经captureScene同步绘制，不把旧像素当当前截图。

无媒体先做代码预检查和示意图验证，有媒体再做`--assets`及正式流程；原程序观察使用隔离副本，不修改原版输入或玩家存档。精确来源缺失时写明，不能补造原版结论。

## 来源、案例与报告

解析器的合法、变体、截断与非法输入按实际格式覆盖；来源预期来自独立推导、原字节或独立核对路径，不用导出器自身计算答案。解析器变化核全部受影响输入，新增同格式内容只增内容核对。

阶段案例至少声明稳定身份、机制、来源前置／开始档、实际操作与节点、预期旗标／队伍／库存／地点差异、重进和关键失败恢复。当前尚未统一案例运行器，沿已有测试辅助与真实来源组织，不另写区域专用VM。

测试辅助放`tests/helpers`，不导入被忽略的evidence执行代码；清单每个测试文件登记一次，并声明层级、范围和环境。报告只由统一入口`--report`写新目录，保留选择原因、执行／复用范围和指纹。

浏览器记录开始／结束档、操作、配置模式、资源与环境身份、截图／录屏、可见结果和世界差异；调参、受控RNG及开发授予单列。原GAME、来源静态核对、规则回放、仅渲染恢复、重制页面与自然主线分别标明。

历史报告保留原范围和原字节，新观察不覆写旧日期记录。版本验收还需独立干净检出与声明输入的生产链，首次构建尚未打通的任务不会因测试改造自动关闭。相关材料见[本地资料](../local_materials.md)。
