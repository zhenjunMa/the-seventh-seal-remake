# 第七封印 · 实现架构

路径以`runtime`为基准。本文维护模块、状态和生命周期边界；字段与接入步骤见[配置指南](config_guide.md)、[剧情指南](story_guide.md)，当前范围见[开发计划](../assessment/validation_design.md)。

## 启动与模块分工

`serve.py`提供`web/`静态文件和固定存档接口；`web/app.js`装配控制器，最后由boot加载内容、配置和视图。现有地图、剧情、菜单等适配仍使用共享`state/actions`；战斗只接收`battle_host`声明的数据访问、显示及菜单接口，不取得整个共享对象。固定Phaser 3.90.0随代码提供，正式入口使用WebGL、640×480逻辑平面，无CDN依赖。

| 位置 | 职责 |
| --- | --- |
| `web/controllers/` | boot、输入、地图、剧情、菜单、经济服务、战斗、存档及诊断的浏览器连接 |
| `web/core/` | 来源校验、规则、资格、RNG、事务和可保存状态 |
| `web/*_view.mjs` | 菜单、对白及其他既有界面的焦点、绘制描述与语义DOM |
| `web/phaser/runtime.mjs` | 引擎、阶段到场景映射、暂停原因、缩放、同步截图和释放 |
| `web/phaser/scenes/` | 探索与战斗场景，各自拥有update、动作时钟和显示对象 |
| `web/phaser/actors/`、`components/` | MapActor、SpritePose和ActionClock；只持有可重建的显示状态 |
| `web/phaser/rendering/` | 分页纹理缓存、BattleSurface、共享界面合成器、GPU转场和实例化像素管线 |
| `tools/`、`tools/source/` | 构建与只读解析；输入到`web/data/`和`web/assets/`的生产链 |

Phaser关闭内建输入和音频，由既有控制器统一处理。规则不写进Sprite、view或`app.js`；实验复用方向为prototype→runtime，正式运行及构建不读取实验目录。

## 状态与提交

| 持有者 | 状态与提交边界 |
| --- | --- |
| WorldStore | 地点、队伍与候补、资源／成长、背包、旗标、队列、技巧／晶石、当前地图NPC块、遇敌RNG及奖励去重。变更由draft和revision提交。 |
| SceneController | 目标地图准备、进入及回滚。先租用和校验资源，再提交地点／布局；失败保留原世界和场景，过期revision不得覆盖新进度。 |
| BattleController | 本场人物、充槽、按人物保存的指令、动作、资源保留和生命周期。通过planning／commit一次性把结果交还世界。 |
| 浏览器战斗会话 | `battle_sessions`私有持有控制器、视图、HUD、随机流、配置副本、光标及资源等待。剧情战／技巧测试切换完整会话引用，结束只恢复仍属于自己的前一会话；视图缓存由战斗模块持有。 |
| 启动配置会话 | boot读取并编译一次配置；菜单复用冻结的道具、技能源和技能注册表，战斗与技巧测试取得独立副本；刷新页面才重新读取。人物当前资源及成长仍来自最新世界。 |
| 浏览器偏好与临时视图 | 音量、光标、完成标记独立于世界；焦点、动画、租约和加载锁不进入游戏进度。 |

普通与快速存档统一使用原版v2二进制格式，目录仍为`remake/saves/`；普通档为`SaveGame0.Dat`～`SaveGame19.Dat`，快速档为`Game.SAV`，不读取旧JSON文件或浏览器旧档。`native_save.py`在文件边界完成编解码与校验，恢复人物、装备、技巧、旗标、事件和地图状态，保留尚未映射的原始区块；新游戏由正式资源定义生成原版格式。写入使用临时文件和同目录原子替换，固定00～19与quick接口沿用If-Match／If-None-Match。服务仅接受本地同源请求，不暴露原程序、evidence或任意文件路径。具体连接见[save_storage](web/core/save_storage.mjs)、[原版编解码](native_save.py)及[本地服务](serve.py)。

存档列表只返回原存档头中的队伍、地图、累计时间及已有缩略图，不构造世界状态或传输完整存档。RGB565缩略图像素原样包成浏览器可解码的BMP，缺图留空，不重建场景或重新生成PNG。服务按文件身份、大小、纳秒修改／变更时间缓存摘要；文件替换或修改后重新读取。列表指纹使用原文件SHA-256，覆盖时按同一指纹核对；确认读取后才完整解码及校验所选存档。

标题和游戏内读取列表在快速档可读时将其置顶，缺少快速档则不显示该行；普通栏位保持原编号顺序，选择保存的页面仍只提供00～19普通栏位。

累计游玩时间和音频／战斗游标设置是可保存世界数据；会话时钟在标题暂停，在成功读档或新游戏时重设，写档时捕获当前设置和累计值。累计时长映射原版头`+0x7D`的100毫秒计数，原版列表`479D70→469D60/469CA0`也读取此值，不与保存日期混用。地图DAT需先转换为原版运行人物，再覆盖当前NPC姿态；场景层码与显隐分开保存及参与显示／交互。原版镜头使用正式导出的有效地图格边界计算，未移动的原档保留其实际镜头。

重制版将头`+0x6D`的16字节SYSTEMTIME区约定为保存日期，按北京时间写入年、月、星期、日、时、分、秒、毫秒；该语义是重制版约定，原版字段用途及原GAME动态兼容尚缺复验。普通／快速保存及游戏内导出由服务端提供当前时刻，编解码器只有显式传入`saved_at`才更新时间，来源核对和修复工具默认保留原字节。完整读取和列表摘要优先返回文件内有效日期，旧档日期全零或非法时回退文件修改时间，并用`saved_at_source`区分`save`／`file`；读取不补写旧档。

新游戏与读档共同产生WorldStore，剧情、菜单、战斗和奖励依据当前状态及正式资源规则运行。`source`记录来源与核对证据，不以存档来源或初始化入口决定流程资格。

战斗启动、选人、提交命令和行动结束只返回轻量表现快照，不遍历或复制历史。完整`snapshot()`仅供显式诊断读取。运行时以`lastBattle`只保留最近一场的状态与结算结果；下一场真正开始记录时清理上一场详细历史和运行事件，不累积多场归档。技巧测试／剧情战斗恢复旧控制器后，最近一场记录仍独立保留。导出运行记录v3以`current_battle`提供最近一场、`battle_result`提供结算结果，不再输出`battle_history`；本场历史仍按原策略追加。

菜单通过`battleMenuState`读取人物摘要及按需复制的背包，通过`chooseBattleItem`下令、`focusBattleMenu`交还焦点；输入和菜单不访问战斗控制器／HUD内部对象。战斗道具配置留在本场会话，不临时替换野外菜单配置。`lastBattle`诊断记录和跨战斗行动优先级仍由应用适配持有，剧情失败的回滚边界沿用完整事件事务。

## 时钟、暂停与取消

| 时钟 | 正式入口的使用者 |
| --- | --- |
| `exploration.clock` | 地图、ANM、物件动作、对白打字／画像、字幕、剧情wait；序章加载显式使用此时钟 |
| `battle.clock` | 充槽、动作接触、生命周期、结算演出与跳过输入 |
| `runtime.clock` | 共享入战转场和默认加载展示 |

ActionClock由所属Phaser场景的delta推进；休眠／暂停不推进，唤醒／恢复首帧丢弃delta。页面隐藏、手动暂停和错误挂起采用原因集合，全部解除才恢复。战斗沿原51BB90门控：充能满20ms后每次主循环只推进一次，从当前时刻重新计时并丢弃超时余量。状态周期读取实际场景时间，独立于充能门控；结束或中断立即停止推进。

`controllers/story.playStory`为序章、到达剧情、NPC和物件建立唯一StoryPlayback，嵌套TLK／ANM共享信号。暂停时不接受对白确认；取消／错误阻止后续指令与提交，并清理对白、字幕、临时演员和按键。异步返回须先核对会话和信号；pagehide及引擎错误中止会话。

独立工具视图可有浏览器计时退路；正式入口注入场景时钟。菜单／启动页仍接收绝对now，媒体持有独立句柄和暂停处理，其完整全局边界按计划复验。

## 内容生产与数据归属

```text
原版只读输入 → tools/source与导出器 → 来源表／媒体
runtime_content.json＋web/content → 能力检查与内容编译 → 运行登记／剧情包
来源表＋data/config稀疏参数 → 启动配置快照 → 世界规则与视图
```

`data/runtime_content.json`是唯一编辑登记；`content_registration.py`直接读取它选择生产输入。chapter-maps／chapter-story准备来源，story-check遍历显式入口的完整可达分支，未知条件、变更、演出或资源能力阻断生产；最终内容编译再次检查。

`export_content_registry.mjs`生成`data/runtime_content.mjs`，boot比较编辑定义快照并拒绝未编译登记。添加登记不自动入队、学习、发奖或实现机制。

| 数据 | 职责 |
| --- | --- |
| `data/config/` | 唯一数值编辑位置，身份与来源指纹只读；稀疏`parameters`合并到来源默认值 |
| `data/library/`及`data/items.json` | 全量静态来源与按原编号的配置引用；来源收录不等于可执行 |
| `data/party_*`、`forest_*`、`enemy_*` | 来源及可执行输入；部分forest命名保留兼容，不另作手工调参表 |
| `data/maps/`、`assets/maps/` | 地图结构与媒体；catalog保存资源身份，运行登记限制开放交互 |
| `data/chapter_story.json`等来源表 | 保留原记录、偏移与字节，供来源及仍需原记录的运行适配核对 |
| `web/content/`、`data/story/` | 前者为独立事件／任务编辑内容，后者为生成的共享、分地图和序章运行包 |
| `data/source/`、`tools/layout_migration.json` | 历史基础清单与迁移映射；原字节不重写成新验收 |

原来源／媒体和部分台账不随Git提供。生产依赖、首次构建限制与历史恢复见[本地资料](../local_materials.md)。

## 探索与剧情

地图控制器提供加载、视口、移动、NPC与交互适配，由探索场景update驱动。`MovementMap`处理地形及连续脚底扫描／滑墙；`KeyboardMovement`保留每个微步已接受的接近／滑动路程，实际完全受阻后才按496AC0／496F90的八邻格顺序与严格小于的曼哈顿评分重选方向，不保存长路径。原两格外目标仅用于评分，不叠加成连续脚底之外的远距离碰撞；候选有可接受的滑动也可选取。这是连续移动适配，非原版逐条等价移植。DAT145决定键盘步长（现登记图为4px），旧字段名`native_camera_step_shift`继续兼容；DAT144仍用于既有速度适配。`map_locomotion`统一玩家、剧情和普通NPC的源速度与按距离步伐。

显示、碰撞和交互距离共用NPC连续显示位置。NPC被玩家阻挡时保留目标和路径、暂停源步进，玩家让开后继续；原自主选择与持久遇敌RNG分开。玩家遇阻后的沿墙、改向和顶墙往返均为真实微步，主体、阴影与跟随相机共用该位置，动画和遇敌按每段实际路程累计，不能以一帧首尾净位移抵消往返。背向输入的回摆保留输入朝向，避免每微步翻面形成双重残影；沿墙和正常绕行仍按实际方向显示。每4px计一步，字节计数器保留前40步免检、255回绕与原概率阈值；碰到出口／新剧情入口或遇敌即停止本帧余下移动。完全无可走邻格不空计步。旧存档0～16的余量继续表示一个微步的完成比例，不重算历史路程。瞬时身体回缩仍只影响显示；原对角接点、脚底扫描与障碍入口的兼容规则见[区域方法](../assessment/region_remake_workflow.md#来源规则速查)。

`map_presentation`产生只读显示描述；MapActor／SpritePose按地面Y组合逐帧阴影、主层与加色层。`map_scene_view`保留给缩略图和几何对照，OpeningView提供演出描述与兼容绘制。阴影alpha等现有适配不声称原16位混色等价。

TLK、自编事件和旧核对事件统一编译为StoryFlow，由`StoryFlowRunner`执行；ChapterRunner提供世界事务与游戏行为。`events.mjs`只保留来源核对适配，正式入口不使用旧native-entry提交。

地图到达`maps.entry`与加载布置`maps.setup`职责不同：前者只在真实进入时与地点一起提交，后者在准备、恢复和缩略图时只读投影NPC。读档优先恢复目标存档的世界和NPC块，不重播到达事件。普通换图重新加载来源布置，不永久缓存各图NPC。

StoryRepository启动只读索引／共享包，地图与序章按需读取；四图缓存保护当前和准备中的图。多图ANM按真实加载和调用关系租用资源，共享程序在最后持有者释放后回收。任务阶段从既有世界事实推导，奖励仍在剧情事务提交。

剧情战使用私有WorldStore，正常结果合入外层draft；后续演出失败仍回滚整条事件。队友入队／离队由`party_members`统一处理，候补保留原实例与成长，四槽不压缩，满队不强制替换。

地图和剧情分别提供探索画面、对白／遮罩的捕获与恢复句柄，战斗经`battle_host`组合交接，不直接修改地图镜头、地图名或剧情DOM。恢复句柄只恢复显示与控制阶段，不修改世界、不重播剧情；剧情限制玩家操作时仍保留探索时钟供演出推进。异步HUD准备与入场同时核当前会话，旧会话清理不得清空新HUD。

终章请求由完整演出提出，世界提交后切标题并禁止resume；到达事件经`SceneController.afterCommit`衔接。该路径可保留隐藏控制角色的原坐标，不增造归位传送；完成标记单独保存在浏览器，不自动写游戏存档。

## 战斗与资源

encounters按已登记地图DAT／STG与持久RNG产生敌组。属性、配置、技能和AI共用正式来源；`combat`等core模块负责公式、状态、选招、命中、成长与奖励，view只消费显示描述。入战组装同步只读所属`WorldStore.value`，不为读取人物和技能复制整个世界；工厂及战斗控制器创建独立的本场单位和背包。技巧测试与剧情战斗仍使用各自的私有世界，结算事务和加载期间的revision检查保持隔离边界。

编成引用各成员已编译技能，按保存顺序合并动作，分别使用成员的参数、消耗、熟练度和接触来源。学习状态、等级与处理器支持独立门控。输入资格与行动资格独立：入场完成后，未确认指令且未执行自身行动的存活人物可在充槽、技能准备量及受击反应期间选择招式和目标；首次开放输入、轮转到其他可下令人物及同一人物下一轮开放输入时，先停在人物选择层；空格／Enter确认后才进入该人物的轮盘，Esc只将轮盘焦点退回人物选择，保留轮盘图标和开放外观；轮盘遮罩仅在当前人物有已确认但尚未发起的指令时显示，行动发起后恢复开放外观，输入仍等待自身主动作结束后解锁。单人队伍也遵循此流程。已确认进入轮盘后，其他人物满槽或当前人物受击不切走输入焦点。招式或道具指令确认后锁定该人物，等待满槽及受击／恢复条件满足才执行，自身主动作（含归位）结束才解锁下一轮输入。指令按人物保留，受击恢复不清除已确认指令；恢复计数与执行门控同步归零。道具确认时保留数量，原使用接触才消耗；不能借用其他人的指令。

战斗INFO随当前输入层显示名称：人物选择显示当前可下令队员，轮盘显示当前选项，招式／物品列表显示当前条目，目标选择时，单体技能／物品只标记选中单位并显示姓名，全体技能／物品同时标记符合资格的作用目标，显示“敌方全体”或“我方全体”。预览从控制器读取有效CHR范围、物品全体标记及既有目标资格，组合技合并各段作用范围；目标光标逐个使用各单位位置与高度。焦点移动、列表滚动、目标失效后自动切换及逐层取消均同步刷新；指令确认进入等待调度时清空，随后自动选中其他可下令队员时显示新队员姓名。

进攻者完成整套攻击与归位源序列后才释放全局行动权，下一人物由原充槽与优先级仲裁；攻击主体结束仅作观测，不提前交棒。目标受击、倒地保持、起身与独立效果继续共用场景时钟，不阻塞其他已就绪人物的选取。控制器分别持有自身主动作锁和整条播放锁，终局与资源释放等待全部尾部完成。新受击可中断当前主动作或替换旧反应，中断完成后释放行动权，旧回执只作用于对应动作与序列票据。连击随目标真实恢复待机或进入起身清零，不在每段受击片段结束时清零；上中下段、倒地／浮空时长与满槽受击门控仍按既有来源规则执行。

BattleView通过BattleSurface把裁切、平移、缩放、加色及文本转换为复用的Phaser对象。背景先准备和绘制，队伍最多4人、敌人最多6个。人物按固定站位及当前地面轨迹定位，所有战斗分支均逐帧按地面脚点Y从小到大绘制，使靠下的单位覆盖靠上的单位；攻击、反击及归位随当前路径更新，浮空Z只移动身体，不改变地面排序。单位的阴影、本体与加色层一起按该顺序提交，效果／HUD在其后分层。反击、独立载体、死亡和复活使用同一规则时钟；死亡完成才可终局，复活epoch使旧回执失效。显示HP和原死亡类别分别处理。

野外遇敌与技巧测试共用`enterBattle`，统一准备人物、战场、HUD、转场和入场，模式只决定样本规则、私有世界及结果返回。入口先启动GPU转场，跨过两个场景更新边界后才开始资源准备，使菜单点击和地图更新两种调用时机都留出首帧显示机会；首帧由实际Phaser `postrender`记录，资源准备起点另记。启动画面出现后预热共享战斗清单，图集清单校验和入场／HUD纹理上传按时间预算让帧。加载较慢时白闪保持全白，其余转场保留末帧，直到战场准备好，不显示地图加载页。

资源就绪后，在转场内按共同来源时间顺序准备各自入场动作的隐藏前段，推进到首个可见姿态后冻结，并将其纳入战场快照；场外跑入保留初始移动帧，不跳过后续跑动。显现模式仍由战斗控制器选择一次，声音帧延后至首次实时绘制播放，取消或重进清除待播声音与姿态。仅平移各人物的显示时间戳，不推进场景时钟、不提前确认入场完成。转场结束进入`battle-entry`，从准备姿态继续各自剩余的入场序列。全部入场回执完成后才开始充槽、状态计时和战斗操作，入场耗时不补算为战斗逻辑步。敌我首次蓄力从内部`0`（可视半槽）开始，后续普通攻击从内部`-threshold`（空槽）开始，均按既有速度增长至`+threshold`满槽；经过内部零值时不清空显示。技能准备量沿用独立计数，倒下人物不绘制充槽填充。

CHR command9/mode4依原DGP宽度离屏放置，再由`core/battle_entry`沿八像素来源点返回保存站位；生命周期与接触反应共用点列，原跑动记录在抵达前循环，控制器持有坐标和免疫变更。command1非等待X／Y抖动由`core/battle_camera`保留20ms步进，使用同一场景时钟并随战斗退出清理。其余镜头移动继续使用既有固定战场平面适配，源帧间插值不作为原生投影精度声明。

受击反应使用各DGP动作的原间隔，不附加攻击预览的收尾等待；落地／起身回执衔接期间保留上一显示姿态。存活角色的id4倒地末帧按510900启动F692=5000保持，502F30每次充能检查使用该动作fixed+E3/E7与状态速度消耗；期间停止通常充能、准备量和F6A2/F69E递减，到期余量加入行动槽并当次衔接id6起身。该保持只在sprite末帧初始化，控制记录结束及待完成回执重试不重置。人物浮空与动作共用门控，每次主循环至多推进一次来源记录；先更新高度，等待高度时用20ms间隔，非等待时由同次DGP动作覆盖间隔。零时长控制记录的下一记录也等下一次主循环。正伤害按原分支累计fixed+0x12D恢复量：普通接触取攻击者，效果接触取目标当前技能；防御／闪避、新致死和已有恢复量时不累计，动作结束剩余值大于99才换算额外恢复等待。战斗阴影读取同一物理帧的DGP遮罩，随动作更新并保持地面高度；遮罩与身体共用锚点，图集保留原空帧。逃跑成功先按state11排除指令和目标，再播放选定的type10动作向场外移动，离场回执完成后才允许对应战斗结束；逐人成功判定不变。

敌人待机沿原51A4F0的判定，在HP不高于原最大HP的四分之一时使用CHR id7；原状态bit8及恢复量也共用此动作。条件解除后回到id0，攻击／受击期间保留当前动作。两种待机共用调度器时钟、逐记录命中类别和显示描述，只在切换时重置动作游标；id7贴图随本场基础姿态预载。

## 菜单、经济与音频

菜单控制器通过core事务连接装备、药品、技巧、队列和晶石；焦点及草稿由对应子视图管理。切页只刷新当前页，人物与摘要按世界对象、revision及配置身份复用；读档替换、世界事务或配置变化后重算。技巧页共用同一份有效技能源，先更新数据再绘制，避免隐藏页重建、重复复制世界和重复生成技能源。

打开菜单只准备默认人物页，不复制完整运行配置、不重建地图HUD；未进入的子页不重置。物品选择独立于背包筛选，语义按钮保留全部条目，可见行共享固定数量的图片与文字画布；技巧列表复用六行，滚动只重绑列表，普通移动只更新前后选中行、INFO和预览。人物摘要、属性、装备／法器对比及物品目标栏保留数值画布；命名与图标选择只更新输入预览。状态提交后刷新当前页，隐藏页在下次进入时读取最新世界。

野外回复技巧结算后保留目标按钮、焦点及数值画布，只更新变化的HP／MP、血条和技巧熟练度／消耗；可用技巧列表发生增减时重建该技巧视图。地图侧栏同步资源，不重建人物和背包。有效技能源只从配置基线重放施法者变化的成长记录，未变条目继续复用；成长记录的解码按对象与原字节缓存，工作字节始终独立，原记录改变后重新校验。

技巧测试进入时保留菜单并冻结输入；界面合成器将当前图片、字形与保留绘制列表捕获为主GPU纹理，转场覆盖就绪后才隐藏菜单。快照持有独立显示对象并随转场释放，隐藏菜单后仍可恢复GPU上下文。测试复用正式战斗和配置，以私有票据恢复原菜单页、交互状态与焦点；药品等真实资源变化仍按已接入规则提交。

城镇kind8服务由`controllers/native_services`连接原菜单视图与`core/native_economy`，金钱、配方、物品资格都在规则层；关闭后继续原对白，整条交互成功才提交。详见[剧情指南](story_guide.md#城镇服务与金钱)。

`core/audio`统一音量、静音与cue；menu_feedback保证单次输入／事务只发一次反馈。战斗动作和特效按源逻辑帧与实例去重，独立载体结束前保留声音访问；剧情媒体持有独立句柄／增益节点，结束恢复地图BGM并释放。缺失原文件保留空引用。

主画面使用`#phaserHost canvas`；启动、加载、对白、字幕、保存、大地图和操作菜单字形的像素层由一个共享WebGL界面合成器绘制，输出跟随原DOM坐标、裁切、透明度和显隐。DOM保留语义、焦点、命中区域及既有静态界面元素；不为每个控件建立GPU上下文。合成器缓存各画布的几何信息，DOM变化只使相关子树的几何失效；无字形的图片变化不触发布局扫描，周期性全量检查仍保留作兜底。战斗HUD的保留绘制列表直接合入BattleSurface，普通与加色通道分别混合。

主画面按显示尺寸与设备像素比选择1～3倍绘制分辨率，规则、镜头中心、UI和输入仍使用640×480逻辑坐标；场景相机统一换算，转场快照保留实际分辨率。`characterPipeline`以一条多纹理管线承载普通图形和人物xBR-lv2，通过顶点元数据区分角色、限制动画帧取样并按实际放大倍数处理透明边缘；非人物和没有放大的精灵直接采原像素。地图主角、NPC及剧情人物主体显式标记，战斗角色／怪物经`drawActorImage`进入同一管线。背景、物件、文字、阴影、加色通道、独立技能效果及死亡粒子不使用xBR。“人物平滑”默认开启，可即时对比，偏好只存浏览器，不写玩家存档。

战斗图集人物帧按占用区域一次拼接并加透明边界，跨页相邻像素在同一帧内参与xBR，锚点与原动作尺寸不变。帧缓存复用原有纹理预算与闲置回收，GPU纹理删除时同时释放对应CPU拼接缓存，避免逐帧重组和重复上传；离屏且未上传的预备帧也回收。地图动画直接使用原图集和帧边界取样，无需复制整张图集。

七种入战转场直接捕获场景到DynamicTexture：碎片／四角使用批量四边形，白闪和逐行效果使用着色器与一次生成的小参数纹理。快照、临时纹理和对象在结束、取消、准备失败及销毁时释放；截图不推进世界或时钟。主渲染与界面渲染的上下文丢失接入同一暂停原因集合，恢复后重建资源、重绘仍在使用的转场快照，再恢复游戏。

纹理页面以2048及设备限制中较小者为上限。大地图拆页，超长人物图集按实际显示区域裁切并缓存；不改原资源、坐标或来源指纹。字形只在内容／样式变化时栅格化和更新纹理。Canvas 2D仅用于辅助字形／小图生成、源像素与传感器读取、图像裁切和工具截图；`#stage`和`#battleCanvas`保留为透明截图／焦点目标。输入监听在退出解绑，运行挂起时清除按键。
