## 编辑与生成的边界

`web/data/runtime_content.json`仍是唯一接入登记。maps选择地图、NPC槽、进入剧情、触发器、物件与出口；programs选择原ANM；`story.events`与`story.quests`显式引用事件和任务文件。未登记文件不自动开放。

`web/data/chapter_story.json`、`opening_program.json`、`data/events/*.json`及`chapter_map_resources.json`是原作来源台账，由既有提取工具生成，保留原字节、文件指纹和证据，不作为手工文案编辑入口。

`web/content/events/`适合存放自行编写的独立NPC事件，`web/content/quests/`存放任务定义。可以按章节或区域建立子目录，每个事件／任务有稳定ID，不按内容在数组中的位置标识。

`web/data/story/`是自动生成的运行包。不要直接修改其中台词或跳转；修改来源或编辑文件后重新构建。

队友、道具和技能引用先查`web/data/library/index.json`；它将原角色编号、原item_id和技能原索引关联到唯一配置。使用`tools/build_content_library.mjs` `--query`或`core/content_library.mjs`查询；同名对象必须选具体编号。MAG原ID有重复，使用system_magic_原零基记录索引。runtime_registered=false表示仅有来源，新增剧情不能绕过接入检查直接执行该技能或安排未接入角色入队。完整规范见[config_guide.md](config_guide.md)的“全量来源与引用索引”。

## 区域来源查询与重访

外层白木森林使用同一内容管线，来源索引为`web/data/library/white_forest.json`，构建目标white-forest-index。原名精确为“白木森林”的M70010／20／30／40／50／60属于本轮；“里白木森林”独立保留。query／map／flag参数与火之谷索引相同，入口脚本为`tools/export_white_forest_index.py`。

CF4直接奖励箱登记handler:keyed-chest，以DAT原对象索引识别；F2按原持有条件检查钥匙，+54起十个DWORD保留奖励顺序，不能把会重建的+48缓存当作元素类别。它不需要TLK入口。无TLK地图的DAT来源表显式标明缺失，对白records保持空，不生成虚构对白流程。

加载演出的31等待同步与32镜头聚焦只影响临时呈现；只读布局投影使用共同的已恢复指令校验，保留NPC变化，存档玩家坐标始终优先。4A5110允许原入口标记处于障碍格；这种原落点不改地形，普通路径仍不能走入。

`web/data/library/fire_valley.json`是独立于运行登记的只读来源索引；`tools/export_fire_valley_index.py`从原DAT／TLK／ANM生成，覆盖报告为`evidence/fire_valley_20261024/source_index.json`。使用`build_runtime.py` `--target` fire-valley-index `--run`刷新；直接执行`export_fire_valley_index.py` `--check`只核对来源和产物，`--query` 英格妮检索名称／台词，`--map` M17030-2查看指定原地图，`--flag` 471:1反查跨地图旗标。

NPC以地图ID＋原槽区分；原名或共用图集不用于合并人物。祭坛M17030、M17030-1、M17030-2保留各自NPC表与地图旗标，共用背景不代表同一状态，也不能按文件后缀推断发生顺序。地图NPC坐标／隐藏字段只是加载默认值，后续ANM的place／hide／move／reveal和旗标条件一并保留。

DAT+0x8A的加载TLK入口与+0x13A的到达TLK入口分别索引；slot499是来源索引项，不自动视为上述任一入口。potential_call_roots包含所有分支的静态可达入口，不表示某个存档状态一定可达。新增重访剧情需同时核对加载布局、到达事件、对白条件、跨区域写入和存读档；不复制一套按“第几次进入”计数的区域状态。

索引不执行未知字段、不创建任务阶段、不启用运行入口。projection_gaps定位尚未投影的TLK字段及运行声明未列出的ANM指令；已知指令的参数、资源和完整分支仍需接入检查与实玩验证。原字段、偏移、文件SHA和来源字节用于回查，运行文本仍通过现有StoryFlow内容管线编译。

`programs.external_callers`保留区域外TLK／DAT对相关演出的调用及结构索引根，不扩大区域地图成员，也不证明当前存档可达。例如m17010-3的M17020描述符31没有cells，另有`M03039.TLK`:r13实际调用；不能从文件名或描述符存在推出进入链已接通。

火之谷来源集保留21张原ID地图、147个NPC实例，其中63个具有独立原对白入口，其余84个没有独立对白入口，仍按原显隐／演出管理。18份TLK共361条来源记录；来源数量不等于入口、分支或主线完成证明。重访阶段取决于真实全局旗标（包含其他区域写入），不能用访问次数替代。全区域阶段验收与剩余卡点只在[validation_design.md](../assessment/validation_design.md)维护；复用方法、来源陷阱和证据交接经验见[region_remake_workflow.md](../assessment/region_remake_workflow.md)。

### 佛兰珂房间如何交接回谷演出

原`Map/m03039.dat`的地图旗标为426，加载入口+0x8A与到达入口+0x13A均为0。其TLK索引slot11指向r7，slot499指向r10；两条都是可回查的结构根，slot499存在本身不证明加载时会自动执行。

## 运行结构

`index.json`保存地图包、共享包与序章包的路径和指纹，并绑定当前接入登记。

`shared.json`保存共用角色、物品定义及任务定义；`maps/mxxxxx.json`版本2保存统一的flows流程表、NPC入口、ANM、交互资源与texts文本表。TLK、旧侦探样本和自行编写的事件全部编译为seventh-seal-story-flow版本1；文本编号按地图＋TLK记录号、选项编号或事件＋稳定句子ID生成。

原对白字节与正文的一致性、已登记分支能力、跳转及来源绑定在编译时检查。运行主线对白不再携带1647字节TLK原记录；仍供物件、人物运动、道具初始化及ANM执行器使用的原记录保留。

浏览器启动只加载清单和共享包，进入地图前加载对应剧情包，开始新游戏时加载序章包。默认保留最近四张地图，当前地图及正在准备的地图受到保护；活动准备超过容量时暂时保留，后续加载回收。加载失败可重试，安装前校验完整包，加载不会修改世界进度。

运行事件只有`core/story_flow.mjs`中的StoryFlowRunner负责命令执行。ChapterRunner提供统一的世界事务、对白、选项、物品、休息和ANM行为适配，火之谷与炎城NPC都从这里进入；chapter记录仅保留来源绑定、物件和地图索引，不再另行解释一遍TLK控制流。

炎城侦探是开发验证片段，保留首次／重复交互和未恢复分支提示，不代表炎城主线已贯通。它现在也采用完整事件成功后提交；中断或失败不会消耗任务旗标。旧存档的旗标、物件记录、入队和奖励去重语义沿用原规则。

正式播放的生命周期由`controllers/story.playStory`与`core/story_playback.mjs`统一管理：序章、地图入口及交互事件各有一个会话，嵌套TLK／ANM共用取消信号。对白、字幕、动作和剧情wait均受探索场景时钟控制，暂停后不响应确认／选择，恢复后继续剩余时长。中止／失败沿用事务回滚并清理临时表现，不按成功处理；结束清理完成前不启动下一段事件。新增行为需传递playback／signal，等待使用`playback.wait`或场景时钟，异步资源返回后先检查信号再安装场景或修改草稿。

`core/events.mjs`仅供旧来源核对工具使用：它将旧program转换为同一种StoryFlow并调用同一个执行器，不包含另一套解释循环；历史native-entry提交观察只存在于该核对适配器，正式入口不使用它。

## 新增原作地图或NPC

1. 按[config_guide.md](config_guide.md)从原DAT／TLK确认入口、NPC原槽、地图旗标和所需ANM，在runtime_content登记。普通NPC使用原槽编号，npcs显式列表可限制开放范围。

2. 执行chapter-story准备来源，再执行`--preflight`查看能力缺口。登记不会自动实现未知条件、指令或奖励机制。

3. 执行content完整构建。最终内容编译会同时生成剧情包，无需为新地图增加专用Scene、控制器或手写route_events表。

4. 从正式入口核对进入、交谈、选择、任务推进、奖励、退出、重复进入及存读档。图像和音频仍由原资源构建链提供。

## 新增独立NPC对话

在`web/content/events/`中创建一个seventh-seal-story-event版本1文件，再将相对web的文件路径加入`story.events`。例如以下只是格式示例，不会自动接入游戏：

```json
{
  "schema": "seventh-seal-story-event",
  "version": 1,
  "id": "fire-valley-villager-example",
  "map_id": "M17020",
  "npc_slot": 10,
  "program": [
    {"op": "say", "id": "greeting", "speaker": "火妖精", "text": "一路小心。", "style_raw": 2},
    {"op": "end"}
  ]
}
```

npc_slot绑定地图已导出的原NPC，不重复创建人物。同一个NPC只能登记一个独立事件，在该事件内处理首次、重复与任务阶段分支。独立人物也可用npc提供既有事件格式的id、名称、坐标、朝向与图集resource，替代npc_slot；它仍需要真实可用的媒体。

每句say必须有稳定且唯一的id，修改台词时保持id不变。跳转支持命令label以及字符串target／if_true／if_false，构建时解析为运行地址；不要依赖手算数组下标。

say可指定style_raw:0至3、portrait_id（0为无画像，其他为已有画像编号）及portrait_left。绑定原NPC时，思考对白沿该NPC头部定位。

当前编写入口支持say、旗标判断／变更、跳转、等待与物件状态等指令。原TLK的选择、物品、休息、存档请求和ANM同样编译到统一流程，入队仍由ANM行为适配器调用既有通用入队规则；来源绑定继续按原事件登记。新增指令先实现通用处理器和导入映射，再接入内容。

所有正式事件采用成功后原子提交，失败不消耗任务旗标。自行编写事件的来源在构建时标为authored，不伪造原作证据。运行NPC入口只引用flow_id，不携带旧program或区域专用commit_policy。

NPC可用conditions:[{"index":原旗标索引,"value":原完整旗标值}]限定显示／交互资格；原地图的可见与移动状态继续由原记录解释。

## 新增任务

每个任务文件使用seventh-seal-quests版本1和quests数组，路径登记到`story.quests`。已有样本是`web/content/quests/fire-valley.json`，描述现有邀请凯与领取装备的准备流程。

任务包含id、name、maps与有序stages；阶段包含id、status、text、when。按顺序选择第一个满足条件的阶段，因此通常先列完成／失败阶段，再列进行中阶段，最后可用{"all":[]}作为默认阶段；没有匹配阶段时隐藏。

status可为hidden、available、active、completed、failed。when支持all、any、not、flag:{index,bit,value}和party_member:"原角色ID"，只接受声明式数据，不执行脚本表达式。

任务进度通过`storyRepository.journal`(world)或`core/story_quests.mjs`的questJournal查询，控制器也会更新`state.questProgress`，供后续任务界面使用。本次不改变现有菜单布局。

任务定义只观察世界状态，不发奖励、不自动写旗标，也不另存一份任务进度。奖励仍由剧情事务执行，并使用原事件状态／旗标防止重复领取。新增原作任务先核对其真实旗标；新增独立持久状态或未恢复的任务条件需要相应实现与存档设计。

## 构建与检查

只修改独立事件、任务文件或story中的事件／任务登记：

```console
python3 -B remake/runtime/tools/build_runtime.py --target story-pack --run
```

此步骤复用已有来源台账和已编译地图／角色身份，不依赖本机原版安装；不重新提取或声称已核验原始文件。只允许快速刷新story登记，地图、角色或ANM登记变化必须走content完整构建。

只读核对剧情包是否过期：

```console
node remake/runtime/tools/export_story_packages.mjs --check
```

正式代码预检查已包含上述核对：

```console
node remake/runtime/tools/verify_phaser.mjs
```

新增对白文字也被dialogue-ui的字体收集读取；需要新增原字体字形时执行对应字体／UI构建。新地图、原素材提取和完整content构建仍需要[config_guide.md](config_guide.md)与[README.md](tools/README.md)声明的原作文件和本地前置材料。
